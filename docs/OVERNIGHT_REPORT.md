## 1. 한눈에 보기

- **결정 사항**: X-Pool(CVPR 2022)을 MSR-VTT 9k/1k-A 전체 데이터로 재현하고, 한계를 분석한 뒤 개선합니다.
- **준비 완료**: 재현 코드, Colab 노트북 3개, 분석/아이디어 선별 도구, 데이터 통계, 로드맵과 협업 규칙 문서. CPU 테스트 8개가 모두 통과했습니다.
- **아직 모르는 것**: GPU와 실제 데이터가 필요한 세 가지, 즉 ① 공식 체크포인트가 우리 파이프라인에서 46.9를 내는지 ② 학습 1회에 몇 시간이 걸리는지 ③ 다운로드 링크가 살아있는지입니다. 이걸 확인하는 게 **오늘 할 일 1번**(go/no-go 노트북, 약 1~1.5시간)입니다.
- **중요 발견 3가지**:
  1. 공식 코드는 **테스트셋으로 best 모델을 고릅니다.** 보고서에서 genuine understanding을 보여줄 포인트입니다.
  2. 최신 torchvision에서 그대로 돌리면 **테스트 이미지 전처리가 조용히 달라집니다.** 원인을 찾아 수정했습니다.
  3. X-Pool의 풀링은 **프레임 순서를 바꿔도 결과가 같은 구조**입니다. 한계 분석 1순위 후보입니다.

## 3. 밤사이 한 일과 결과

### 3-1. 공식 X-Pool 코드 정밀 분석 → `docs/BASELINE_XPOOL.md`
코드를 한 줄씩 읽고 논문에 안 나오는 실제 설정을 정리했습니다.
- 프레임: 학습·테스트 모두 **uniform 12프레임**(각 구간의 가운데 프레임). 이 덕분에 프레임을 미리 뽑아 저장해도 결과가 같습니다.
- 학습: CLIP 전체를 fine-tuning합니다. CLIP 부분 lr은 1e-6, 새로 추가한 풀링 부분은 3e-5입니다. batch 32, 5 epoch(28,125 step), seed 24.
- **평가와 모델 선택**: epoch당 10번 테스트셋으로 평가하고, 최근 5회 R@1 평균이 가장 높을 때 `model_best.pth`를 저장합니다. 즉 **논문 수치 46.9는 테스트셋을 보고 고른 모델의 점수**입니다.
  - 대응: 우리는 공식 방식(best-on-test)과 "마지막 체크포인트" 성능을 **둘 다** 보고합니다. 우리 방법에도 같은 기준을 씁니다.

### 3-2. 2026년 환경 호환성 문제 3건 발견 및 수정 → `src/tvr/compat.py`
| 문제 | 영향 | 수정 |
|---|---|---|
| 최신 torchvision은 resize할 때 antialias가 기본으로 켜져 있음(2022년 원본은 꺼져 있었음) | 모든 테스트 이미지가 달라짐 (최대 픽셀 차이 약 0.13) → 재현 수치가 어긋날 수 있음 | `antialias=False` 고정 |
| 공식 체크포인트에 있는 `position_ids` 버퍼 2개가 최신 transformers에는 없음 | 체크포인트 로딩 에러 | 그 2개만 제외하고 나머지는 엄격하게 로딩 |
| PyTorch 2.6+ `torch.load` 기본값 변경 | 로딩 에러 가능 | 안전하게 처리 |

방법(모델)은 하나도 바꾸지 않았고, 원본과 같은 결과가 나오도록 맞추는 수정만 했습니다.

### 3-3. 재현 파이프라인 → `src/tvr/`
- 공식 코드를 **고치지 않고 감싸는(wrapper)** 구조입니다. 덕분에 "공식 코드 그대로 재현"이라고 말할 수 있습니다.
- **프레임 캐시**: 영상에서 12프레임을 한 번만 뽑아 저장합니다. 매 step마다 mp4를 디코딩하지 않으니 학습이 빨라집니다. 원본 디코딩과 **비트 단위로 같음**을 자동 테스트로 확인했습니다.
- **자동 기록**: 실행마다 `run_meta.json`(GPU 이름·메모리, 피크 메모리, 총 학습시간, 라이브러리 버전, 커밋)과 `eval_history.jsonl`(50번의 평가 전부)을 남깁니다. 과제의 Dataset Criterion이 요구하는 연산 환경 보고 항목을 그대로 채울 수 있습니다.
- **Colab 끊김 대비**: epoch이 끝날 때마다 상태를 저장합니다. 노트북을 다시 실행하면 이어서 학습합니다.
- **벤치마크 모드**: 200 step만 돌려 전체 학습 시간을 추정합니다.

### 3-4. Colab 노트북 3개 → `notebooks/`
| 노트북 | 하는 일 | 예상 시간 |
|---|---|---|
| `00_go_no_go` | 데이터 다운로드(Drive에 사본 저장) → 프레임 캐시 → 실제 영상 50개 동일성 검증 → 공식 체크포인트 재평가(46.9 기대) → 200 step 속도 측정 → **GO/NO-GO 자동 판정**과 `go_no_go.json` 생성 | 1~1.5시간(첫 실행) |
| `01_train_baseline` | seed별 전체 학습 → best와 last 평가, 분석용 dump, 프레임 순서 probe → 결과 JSON을 repo로 복사 | go/no-go로 측정 |

### 3-5. 데이터셋 통계 → `docs/DATASET_FACTSHEET.md`, `docs/DATASET_FACTSHEET_TABLES.md`
공식 annotation 파일에서 직접 계산했습니다(Proposal "Topic & Dataset" 2점 항목용 근거).
- 영상 10,000개, 캡션 200,000개(영상당 20개), 총 41.7시간, 클립 길이 10~30초(평균 15.0초)
- 9k 학습셋: 9,000영상 / 180,000쌍. 1k-A 테스트: 1,000쌍. **학습과 테스트 겹침 0**
- 9k 학습셋 중 **1,990개는 원래 2016 공식 test split에서 온 영상**입니다. 이 검색 프로토콜이 2016 원래 분할과 다르다는 뜻입니다.
- 테스트 질의 1,000개 중 965개는 MSR-VTT 캡션과 완전히 같고, 35개는 다릅니다.
- 테스트 질의 중 시간어(then/after/before/while 등)가 들어간 것은 63개입니다(한계 분석 H1에 쓸 데이터).
- 카테고리는 20개인데 json에는 번호만 있습니다(이름 없음).
- ⚠️ **라이선스/이용 조건은 직접 공식 페이지에서 확인해 주세요.** 제가 확인하지 못했습니다.

### 3-6. 선행연구 지도 → `docs/RELATED_WORK.md`
X-Pool 후속 연구 9개를 정리했습니다(학회, 핵심 아이디어, 확인된 R@1). 예를 들어 T-MASS(CVPR'24)는 X-Pool 위에 구현해서 46.9 → 50.2를 달성했습니다. 아이디어가 겹치는지 점검하는 표도 있습니다. **교수님 연구실의 Cap4Bridge(캡션 기반)와 같은 방향은 피하도록** 표시해 두었습니다.

### 3-7. 한계 분석 도구 → `analysis/`
- `analyze_dump.py`: 카테고리별, 질의 길이별, 시간어 유무별 성능 / 프레임 순서 probe 표 / hubness(특정 영상이 여러 질의에 반복 검색되는 현상) / 실패 분류(오답 영상의 캡션이 질의와 거의 같은 "라벨 모호성" 비율) / 그래프 3종
- `failure_gallery.py`: 실패 질의마다 정답 영상과 오답 영상의 12프레임을 나란히 놓고, X-Pool이 각 프레임에 준 attention 가중치를 표시합니다(Intermediate의 정성 분석용).

### 3-8. 아이디어 빠른 선별 도구 → `proxy/`
학습된 CLIP 특징을 고정하고 풀링 부분만 학습해서 **아이디어 1개를 몇 분 만에** 비교합니다. full run 1회(수 시간)를 쓰기 전에 거르는 용도입니다. 예시로 "시간 위치 임베딩을 추가한 X-Pool" head를 넣어 두었습니다. 단, **프록시 수치는 보고서에 최종 결과로 쓰면 안 되고** 아이디어 순위를 매기는 데만 씁니다.

### 3-9. 한계 가설과 아이디어 풀 → `docs/IDEAS.md`
- 가설 6개(H1 시간 순서 무시, H2 문장을 벡터 하나로 압축, H3 hubness, H4 라벨 모호성, H5 12프레임 샘플링 한계, H6 고정 attention 온도)
- 각 가설에 확인 방법과 판정 기준을 붙였고, 아이디어 후보 5개(I1~I5)와 겹침 점검 메모를 정리했습니다.
- 도전 트랙(본인 아이디어, 가산점)과 안전 트랙(후속 연구 기법 차용, 베이스라인 초과 보장)을 함께 운영하는 계획입니다.

### 3-10. 협업 체계 → `CLAUDE.md`, `AGENTS.md`, `docs/COLLAB.md`, `docs/HANDOFF.md`, `experiments/LOG.md`
- Claude Code는 `CLAUDE.md`, Codex는 `AGENTS.md`를 자동으로 읽습니다. 둘 다 같은 규칙 문서(`COLLAB.md`)를 가리킵니다.

## 4. 검증 결과

| 검증 항목 | 방법 | 결과 |
|---|---|---|
| 프레임 캐시 = 공식 디코딩 | 합성 영상 6개(길이 9~300프레임, 12프레임보다 짧은 영상 포함), npy/png 두 형식 | ✅ 비트 단위 동일 |

| 분석 도구, 프록시 도구 | 위 미니 실행의 dump로 실행 | ✅ |
| 노트북 문법 | IPython 변환 후 파싱 | ✅ |
| **실제 GPU / 실제 MSR-VTT / 46.9 재현** | – | ⏳ **오늘 go/no-go로 확인** |
