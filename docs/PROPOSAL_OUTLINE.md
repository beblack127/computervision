### 1. 연구 주제 및 데이터셋 (2점)

> 채점 포인트: 과제는 "자세히 쓰지 않으면 점수가 없다"고 명시합니다. 출처, 규모, 라이선스, 전처리, 분할, 샘플링 여부를 **빠짐없이, 구체적인 숫자로** 써야 합니다.

#### 1.1 문제 정의: 텍스트-영상 검색
- 정의: 자연어 문장(질의)이 주어지면, 후보 영상 집합에서 관련 있는 영상을 찾아 **순위**를 매기는 문제
- 두 방향:
  - text-to-video (t2v): 문장 → 영상. **본 프로젝트의 주 평가**
  - video-to-text (v2t): 영상 → 문장. 보조 평가
- 핵심 구성: 텍스트 임베딩과 영상 임베딩을 같은 공간에 놓고 **유사도**(코사인)로 순위를 매김 `[논문: X-Pool §3]`
- 어려운 점 (재료):
  - 영상은 여러 프레임으로 이루어져 정보량이 크고, 텍스트는 짧음
  - 한 영상에 대한 여러 캡션이 영상의 **서로 다른 부분**을 묘사함. X-Pool 논문도 MSR-VTT 캡션에서 이 점을 짚음 `[논문: X-Pool §5.1]`
  - 그래서 영상 전체를 하나의 벡터로 요약하는 방식(어떤 프레임을 얼마나 반영할지)이 성능을 좌우함

#### 1.2 연구 동기: 왜 흥미로운가 💭 [해석]
> 본인의 관심과 문제의 중요성을 연결하는 자리입니다. 아래 재료 중 2~3개를 골라 본인 관점으로 엮으세요.
- 재료 A (응용): 영상 플랫폼, 아카이브, 영상 검색 서비스처럼 텍스트로 영상을 찾는 수요
- 재료 B (기술적 흥미): 이미지-텍스트로 사전학습된 CLIP을 **영상**으로 확장할 때 "프레임을 어떻게 모을 것인가"라는 질문이 생김. 이게 X-Pool의 출발점
- 재료 C (연구적 흥미): 텍스트에 따라 영상 표현이 달라지는 설계(텍스트 조건부 풀링)는 정확도는 올리지만 효율, 텍스트 표현력 같은 새 문제를 낳음. 후속 연구가 활발한 이유 (2장과 연결)
- 재료 D (개인): 영상 분야에 관심이 있는 이유. 본인 이야기 한두 줄
- 💭 질문: "이 문제가 풀리면 무엇이 좋아지는가?", "왜 쉬운 문제가 아닌가?"에 각각 한 문장씩 답해보면 문단이 됩니다.

#### 1.3 베이스라인 선정: X-Pool
- 논문: Gorti et al., "X-Pool: Cross-Modal Language-Video Attention for Text-Video Retrieval", **CVPR 2022** (과제 허용 학회)
- 선정 이유 (재료):
  - 과제 예시 주제(Video Retrieval)의 대표 논문. 교수님 연구실이 익숙한 분야라 피드백을 받기 좋음
  - **공식 코드와 학습된 체크포인트가 공개**되어 있어 재현 결과를 객관적으로 대조할 수 있음 `[측정: 실제로 대조 완료, 1.6절/3.3절]`
  - CLIP ViT-B/32 기반이라 단일 GPU(A100)로 **전체 데이터 학습이 가능**함 `[측정: 1회 약 6.1시간]`
  - 이후 다수의 후속 연구가 X-Pool을 비교 대상이나 출발점으로 삼음(T-MASS는 X-Pool을 베이스라인으로 설정) → 한계 분석과 개선의 기준점으로 적합
- 💭 [해석] 위 이유 중 본인에게 가장 설득력 있는 것을 1순위로

##### 1.4.3 학습/평가 분할 기준 📊 (표 2 권장)
| 분할 | 영상 | 텍스트-영상 쌍 | 원래 2016 공식 분할 기준 출처 | 용도 |

- 분할 근거: X-Pool 논문이 정한 설정을 그대로 사용 `[논문 §5.1]`
  - 9k 학습: 선행 연구의 분할을 따른 약 9,000개 영상
  - 7k 학습: 다른 선행 연구가 정의한 부분집합
  - 1k-A: 선행 연구가 선정한 1,000쌍
  - ✅ 각 분할의 원 출처 논문은 X-Pool 참고문헌 번호로 확인
- 겹침 확인 `[계산]`: 9k 학습과 1k-A 테스트의 영상 겹침 **0개**
- 💡 눈여겨볼 사실 `[계산]`: 9k 학습셋에는 2016년 원래 분할에서 **test였던 영상 1,990개**가 들어 있습니다. 이 검색 프로토콜이 데이터셋 원래 분할과 다르다는 뜻입니다.
  - 원래 분할은 `MSRVTT_data.json`의 split 필드가 모두 train으로 되어 있어, 영상 id 범위로 계산함 (train 0–6512, validate 6513–7009, test 7010–9999)
- 💡 1k-A 질의 1,000개 중 965개는 해당 영상의 MSR-VTT 캡션과 글자까지 같고, 35개는 다름 `[계산]`
  - 원인은 추정입니다. 쓴다면 "추정"이라고 명시하세요.
- **validation 분할이 없음**: 이 프로토콜에는 별도 검증 세트가 없습니다. 3.4절의 "모델 선택 문제"로 이어지는 복선이니 여기서 한 줄 언급하세요.

##### 1.4.4 전처리 (공식 코드에서 확인한 실제 동작)
- **영상 → 프레임**
  - 영상당 **12프레임**을 균일 샘플링: 전체 프레임을 12구간으로 나누고 각 구간의 가운데 프레임을 선택
  - 학습과 테스트 모두 같은 방식 (공식 설정 `video_sample_type=uniform`)
  - 12프레임보다 짧은 영상은 마지막 프레임을 반복해서 채움
- **학습용 이미지 증강**
  - 무작위 크롭 후 224×224로 조정 (원본 면적의 50~100% 범위)
  - 좌우 반전
  - CLIP 평균·표준편차로 정규화
- **테스트용 이미지**: 짧은 변을 224로 bicubic 조정 → 가운데 224×224 크롭 → CLIP 정규화
- **텍스트**: CLIP BPE 토크나이저, 최대 77토큰. 텍스트 임베딩은 문장 끝 토큰(EOS) 위치의 출력
- **우리 쪽 추가 처리** (결과를 바꾸지 않는 최적화이며 검증 완료. 자세한 내용은 3.3절)
  - 12프레임을 한 번만 디코딩해 저장(프레임 캐시) → 원본 디코딩과 **비트 단위로 동일**함을 합성 영상 자동 테스트로 확인. 실제 데이터에서는 공식 체크포인트 재평가가 논문 수치와 정확히 일치한 것이 간접 근거
  - 캐시 생성 760초, 27.6GB `[측정: go_no_go.json]`

##### 1.4.5 데이터 규모 결정: 축소 없이 전체 사용
- 결정: **9k 학습 전체 + 1k-A 테스트 전체. 샘플링이나 축소 없음**
- 근거 `[측정]`:
  - A100 1장에서 1회 학습(5 epoch, 28,125 step)이 약 **6.1시간** → 전체 규모로 여러 번 반복 실험이 가능
  - 영상 디코딩 병목 제거 후 GPU 연산이 병목 (데이터 대기 비율 0.02%) → 가용 GPU를 거의 100% 활용
- 과제 기준과의 연결: Dataset Criterion은 "가용 자원을 충분히 써서 최대한 충실하게 재현하는가"를 봄. **축소 없음 + 실측 근거**로 이 기준을 정면으로 충족

#### 1.5 평가 지표

- **MdR (Median Rank)**: 정답 영상 순위의 중앙값. 낮을수록 좋음
- **MnR (Mean Rank)**: 정답 영상 순위의 평균. 낮을수록 좋고, 순위가 크게 밀린 실패에 민감함
- 주 지표: **t2v R@1** (논문 비교의 기준). 보조로 R@5, R@10, MdR, MnR과 v2t

### 2. 관련 연구 (2점)

> 채점 포인트: 과제 문구는 "베이스라인과 관련 논문이 **어떤 문제**를 다루고 **어떻게** 풀었는지(방법은 상위 수준으로)"입니다.
> 각 논문마다 **문제 → 방법 → 결과 → X-Pool과의 관계** 4요소를 갖추면 구조가 깔끔해집니다.
> ✅ 아래 요약은 원문 확인용 지도입니다. **반드시 원문을 읽고 본인 이해로 쓰세요.**

#### 2.1 배경: CLIP과 CLIP4Clip
- **CLIP** (Radford et al., ICML 2021): 대규모 이미지-텍스트 쌍으로 대조 학습한 이미지·텍스트 인코더. 두 모달리티를 같은 공간에 놓음
- **CLIP4Clip** (Luo et al., Neurocomputing 2022): CLIP을 영상 검색으로 옮긴 대표적 출발점
  - 프레임마다 CLIP 이미지 인코더로 임베딩을 만들고 **시간축으로 모음**
  - 대표 방식: 평균(meanP), 시퀀스 트랜스포머(seqTransf)
  - MSR-VTT 9k t2v R@1: meanP 43.1, seqTransf 44.5 `[논문: X-Pool 표의 비교 행]`
- 핵심 연결고리: 이 방식들은 **텍스트를 보지 않고** 영상 벡터를 만듦(텍스트와 무관한 풀링) → X-Pool이 문제 삼는 지점
- 분량: 짧게 (반 쪽 이하). 2.2를 위한 무대 설정

#### 2.2 베이스라인: X-Pool (CVPR 2022)

##### 2.2.1 문제의식 `[논문 §1, §4.2]`
- 하나의 텍스트는 영상의 **일부**만 묘사함 → 영상 전체를 텍스트와 무관하게 평균 내면 텍스트에 없는 내용까지 섞임
- 장면 전환, 가림, 방해 요소처럼 **내용 다양성**이 클수록 이 문제가 심해짐
- 💭 [해석] 이 주장이 직관적으로 왜 타당한지 본인 예시 하나 (예: 여러 장면이 섞인 영상과 그중 한 장면만 말하는 캡션)

##### 2.2.2 사전 검증: top-k 풀링 `[논문 §4.3]`
- 아이디어: 텍스트와 코사인 유사도가 가장 높은 k개 프레임만 평균 (학습 파라미터 없음)
- 결과: k=3에서 평균 풀링보다 R@1이 높음 (MSR-VTT)
  - ✅ 표에서 zero-shot과 fine-tuned 블록이 각각 어느 쪽인지 원문 표(그림 3 근처)에서 직접 확인하고 숫자를 쓰세요. 추출본에서는 블록 구분이 모호했습니다.
- 한계: 텍스트-영상 쌍마다 최적 k가 크게 달라 하나로 고정하기 어려움 (k 분포 히스토그램)
- 의미: "텍스트에 따라 프레임을 고르면 좋다"는 가설을 학습 없이 먼저 보이고, k를 학습으로 대체하는 동기를 만듦 → 논문 구성의 설득력
- 💭 [해석] 이 "간단한 증명 → 학습 모델" 구성에서 배울 점 (우리 프로젝트에도 적용 가능한 태도)

##### 2.2.3 방법 `[논문 §4.1, §4.4]` 📊 (그림 1: X-Pool 구조도. 직접 그리기 권장)
- 입력: 텍스트 임베딩 1개(CLIP 텍스트 인코더), 프레임 임베딩 F개(CLIP 이미지 인코더, F=12)
- 텍스트 조건부 풀링 (교차 모달 attention):
  - Query = 텍스트 임베딩 (LayerNorm 후 선형 사상)
  - Key, Value = 프레임 임베딩들 (LayerNorm 후 각각 선형 사상)
  - scaled dot-product attention으로 프레임별 가중치 계산 → Value 가중합
  - 출력 사상 + LayerNorm → FC(512차원, dropout 0.3) + 잔차 연결 + LayerNorm → 텍스트에 맞춘 영상 임베딩
  - 수식 흐름: Q = LN(c_t)W_Q, K = LN(C_v)W_K, V = LN(C_v)W_V → softmax(QKᵀ/√D_p)V → W_O, LN → FC + 잔차 + LN
- 초기화: 새 사상 행렬은 **항등행렬**, bias는 0 → 학습 초기에 CLIP의 원래 동작을 해치지 않게 함
- 유사도: 텍스트 임베딩과 "그 텍스트에 맞춘 영상 임베딩" 사이의 코사인
- 핵심 성질 (재료): 같은 영상이라도 **질의마다 다른 영상 표현**이 만들어짐
  - 장점: 관련 프레임에 집중
  - 대가: 질의가 오기 전에는 영상 표현을 미리 계산해 둘 수 없음 → 2.3.1과 연결
- 💭 [해석] attention 가중치가 "텍스트가 각 프레임을 얼마나 중요하게 보는지"라는 점을 본인 말로

##### 2.2.4 학습 목표 `[논문 §4.4]`
- 배치 안의 대칭 교차 엔트로피 (대조 학습)
  - t2v 항: 텍스트 i에 대해 영상 i가 정답, 배치의 나머지 영상은 오답
  - v2t 항: 영상 i에 대해 텍스트 i가 정답
  - 두 항의 합
- 유사도에 곱하는 스케일 λ는 학습 가능하며, CLIP의 값으로 초기화
- CLIP 인코더까지 **end-to-end로 미세조정**함
  - 구현상 CLIP 파라미터와 새 파라미터의 학습률이 다름 → 3.2절에서 다룸

##### 2.2.5 실험 결과와 분석 `[논문 §5]` 📊 (표 4: 주요 수치)
| 데이터 | X-Pool t2v R@1 | 비교 |
|---|---|---|
| MSR-VTT 9k | **46.9** (R@5 72.8 / R@10 82.2 / MdR 2 / MnR 14.3) | CLIP4Clip seqTransf 44.5, meanP 43.1 |
| MSR-VTT 7k | 43.9 | CLIP4Clip meanP 42.1 |
| MSVD | 47.2 | CLIP4Clip meanP 46.2 |
| LSMDC | 25.2 | CLIP4Clip seqTransf 22.6 |
| MSR-VTT 9k v2t | 44.4 (MnR 9.0) | 부록 A |

- 같은 백본(CLIP ViT-B/32)에서 **풀링만 바꿔** 이득을 얻었다는 점이 핵심 주장
- LSMDC에서 상대 향상폭이 가장 큼 → 저자들은 영화 캡션의 모호성을 이유로 해석 `[논문]`
- **내용 다양성 강건성 실험**: 테스트 영상에 무관한 영상을 끼워 넣어 장면 전환을 인위적으로 늘림
  - 평균 풀링은 MdR이 2 → 46으로 악화, X-Pool은 2 → 9로 적게 악화 `[논문]`
- **정성 분석**: 텍스트마다 attention이 다른 프레임에 몰림. 예를 들어 판정 장면을 묘사하는 문장에서는 영상 전체에 퍼짐 `[논문 그림]`
- **프레임 수** (부록 B): 12프레임이 기본. 6프레임은 성능 하락, 그 이상에서는 포화
- **실서비스 비용** (부록 C): 질의를 미리 알 수 없어 프레임 임베딩만 미리 계산 가능
  - 해결책: 평균 풀링으로 상위 P개 후보를 먼저 뽑고 그것만 X-Pool로 재정렬
  - 복잡도가 O(TV)에서 O(TP+V)로 감소. P=100이면 R@1/5/10이 유지됨
- 💭 [해석] 저자들 스스로 비용 문제를 인정하고 우회책을 낸 점 → 2.3.1(Prompt Switch)이 이 문제를 정면으로 다룬다는 연결 문장의 재료
- 💡 논문과 공식 코드의 차이는 3.2절에서 다룹니다(학습률, warmup). 2장에서는 논문 기준으로 쓰고, 3장에서 "실제 재현은 공식 코드 기준"이라고 구분하면 논리가 깔끔합니다.

#### 2.3 후속 연구

> 공통 틀: (1) X-Pool 계열에서 무엇을 문제로 봤나 → (2) 어떻게 풀었나 → (3) 결과 → (4) X-Pool과의 관계, 우리 프로젝트에 주는 시사점 💭

##### 2.3.1 Prompt Switch (Deng et al., ICCV 2023): 효율을 위해 교차 융합을 버리다
- (1) 문제: X-Pool처럼 텍스트를 영상 표현에 섞는 방식은 **질의마다 영상 표현을 다시 계산**해야 해서 대규모 검색에서 효율 문제가 큼 `[논문 초록]`
  - 복잡도: X-Pool·TS2-Net은 영상 수 × 텍스트 수 × 프레임 수에 비례. 평균 풀링(CLIP4Clip)은 영상 수 × 텍스트 수에 비례 `[논문]`
- (2) 방법 (상위 수준):
  - **Prompt Cube**: 학습 가능한 작은 3차원 프롬프트(시간×공간, 기본 6×6, 약 0.1M 파라미터)를 CLIP 이미지 인코더에 넣음 `[논문]`
  - **Prompt Switch**: 각 self-attention 층 전에 큐브의 시간축과 공간축을 바꿔서, 모든 프레임 쌍이 직접 연결되게 함 → 백본 안에서 영상 전체 문맥을 프레임 표현에 주입
  - **CLIP-guided Prompt Aggregation**: 각 프레임의 [CLS]를 query로 큐브에서 정보를 모음
  - **보조 캡셔닝 목표**: 학습 때만 캡션 생성 head를 붙여 세밀한 의미 학습을 유도. 추론 때는 제거되어 비용 없음
  - 보조 목표가 필요한 이유: 영상 검색 학습은 배치 안 음성 샘플이 부족해 대조 손실이 비교적 쉽게 맞춰진다고 봄 `[논문]`
  - 최종 영상 표현: 평균 풀링 → **오프라인으로 미리 계산 가능**
- (3) 결과 `[논문, ViT-B/32, MSR-VTT t2v]`
  - 평균 풀링 버전: R@1 46.1
  - X-Pool 풀링을 얹은 버전: 47.8 (X-Pool 원본 46.9보다 높음)
  - 순위 계산 비용: X-Pool 3.9GB / 3.9초 vs 평균 풀링 버전 2.0MB / 8.1ms
- (4) X-Pool과의 관계와 시사점:
  - X-Pool의 정확도 이득은 인정하되 **비용이 실용성을 해친다**는 반대 관점
  - X-Pool 풀링과 결합하면 더 좋아짐 → 백본 표현 개선과 텍스트 조건부 풀링이 **상호 보완적**임을 시사
  - 💭 [해석] "정확도 vs 효율" 트레이드오프를 본인은 어떻게 보는지 한두 문장
- ✅ 읽을 때 확인할 것: 표의 비교 조건(프레임 수 학습 6 / 테스트 12, 10 epoch, batch 128)이 X-Pool(12프레임, 5 epoch, batch 32)과 다름 → **공정 비교 조건이 다르다**는 점을 짚으면 비판적 읽기가 드러남

##### 2.3.2 T-MASS (Wang et al., CVPR 2024): 텍스트를 점이 아닌 영역으로
- (1) 문제: 데이터셋의 텍스트는 짧고 간결해서 영상의 풍부한 의미를 다 담지 못함 → **텍스트 임베딩 하나(점)**로는 표현력이 부족 `[논문 초록]`
  - X-Pool은 영상 쪽을 텍스트에 맞추지만 **텍스트 쪽은 여전히 점 하나**라는 점을 겨냥
- (2) 방법 (상위 수준):
  - **텍스트 질량(text mass)**: 텍스트 임베딩 주변에 무작위 섭동을 더해 확률적 텍스트 임베딩을 만듦 (재매개변수화: t_s = t + R·ε)
  - **유사도 인지 반경 모듈**: 섭동 크기 R을 고정하지 않고 텍스트와 프레임들의 유사도로부터 계산 → 쌍마다 다른 크기
  - **지지 텍스트(support text) 정규화**: 텍스트에서 영상 방향으로 질량의 경계에 놓인 벡터를 만들어 추가 대조 손실을 줌 → 질량의 위치와 크기를 조절
  - 손실: 확률적 텍스트로 계산한 대칭 교차 엔트로피 + α × 지지 텍스트 손실 (α=1.2). 결정론적 텍스트 손실을 더하면 오히려 나빠졌다고 보고 `[논문]`
  - **추론**: 질의 텍스트에서 M개를 샘플링하고, 후보 영상마다 가장 가까운 샘플로 점수를 매김 (M=20)
- (3) 결과 `[논문 Table 1, MSR-VTT t2v]`
  - ViT-B/32: X-Pool 46.9 → **T-MASS 50.2** (R@5 75.3, R@10 85.1, MdR 1, MnR 11.9)
  - ViT-B/16: 48.2 → 52.7
  - 추론 샘플 수: 샘플링 없음 44.4 → M=5 46.8 → M=10 50.0 → M=20 50.2 (10~20에서 포화)
  - 5개 벤치마크(MSR-VTT, LSMDC, DiDeMo, VATEX, Charades)에서 X-Pool 대비 R@1 +3~6.3%
- (4) X-Pool과의 관계와 시사점:
  - **X-Pool을 베이스라인으로 두고 설정을 그대로 유지**(d=512, dropout 0.3, 12프레임, batch 32, 5 epoch)하며 텍스트 쪽만 바꿈 `[논문 구현 세부]` → 가장 직접적인 후속 연구
  - 단일 A6000 GPU로 실험 → 우리 자원 규모에서도 재현 가능한 수준
  - 비용: 추론 시 샘플링 횟수만큼 계산이 늘어남. 저자들도 언급 `[논문]`
  - 💭 [해석] "샘플링 없이 추론하면 44.4로 X-Pool(46.9)보다 낮다"는 결과가 무엇을 뜻하는지 (학습만이 아니라 추론 절차가 성능의 큰 부분이라는 점)
- ✅ 읽을 때 확인할 것: 반경 모듈의 정확한 식, 지지 텍스트 정의, 그림 2의 파이프라인

##### 2.3.3 Cap4Bridge (Jeon et al., IEEE Access 2026, 한양대 Multimodal AI Lab): 캡션 앵커로 문맥화
- (1) 문제 `[논문 초록]`:
  - 핵심 과제는 정보가 풍부한 영상과 간결한 텍스트 질의 사이의 **의미 간극**을 메우는 것
  - 기존 접근의 두 한계:
    - LLM 등이 만든 **보조 캡션**은 도메인 관련성이 떨어질 수 있음 (Cap4Video류)
    - 텍스트 임베딩을 **직접 확률적으로 모델링**하는 방법은 원래 질의의 의도를 왜곡할 위험이 있음 (T-MASS류)
- (2) 방법 (상위 수준) `[논문 초록]`:
  - **도메인 캡션 앵커 뱅크**: 학습 도메인의 캡션들로 뱅크를 만들고, 관련 캡션을 의미 앵커로 검색
  - **Caption-Guided Cross-Modality Contextualization**: 공유 co-attention으로 앵커를 이용해 **영상과 텍스트 표현을 함께** 보강
  - **Similarity-Aware Stochastic Augmentation**: 노이즈를 질의 자체가 아니라 **검색된 앵커와의 관련도**에 비례해 줌
- (3) 결과: ✅ 원문 표에서 MSR-VTT 1k-A R@1 등을 직접 확인해서 쓰세요. 제가 원문 표를 직접 확인하지 못했습니다.
- (4) X-Pool·T-MASS와의 관계와 시사점:
  - "짧은 텍스트 vs 풍부한 영상" 문제의식은 T-MASS와 같지만, **확률적 보강을 질의에 직접 하지 않고 앵커를 매개로** 한다는 점이 차이
  - 텍스트만 보강(T-MASS)하지 않고 **두 모달리티를 함께** 문맥화
  - 💭 [해석] 2.3.2 → 2.3.3을 "한 방법의 한계를 다음 방법이 지적하는" 흐름으로 이으면 리뷰의 논리성이 크게 올라감
- ✅ 읽을 때 확인할 것:
  - 베이스 모델이 무엇인지 (X-Pool 계열 풀링 사용 여부)
  - 앵커 뱅크를 학습 캡션으로 만드는지, 테스트 때 무엇을 검색하는지 → **테스트 정보 누수 여부**를 어떻게 막았는지 확인하면 깊이 있는 리뷰가 됨
  - 9개 벤치마크 결과 중 MSR-VTT 수치

#### 3.4 평가 프로토콜: 모델 선택 문제와 대응
- 사실: 이 프로토콜에는 validation 분할이 없습니다
  - 공식 코드는 학습 중 **1k-A 테스트셋으로 epoch당 10회(총 50회)** 평가합니다

  4. seed 3개(24, 0, 1)의 **평균 ± 표준편차**로 보고 → 우연에 의한 차이를 구분

### 4-2. 감점을 부르는 실수 (과제 문구: "논리 오류, 부적절한 표현, 이해 부족 = 위반")
- **숫자 불일치**: 같은 값을 다른 곳에서 다르게 쓰는 것 (예: 클립 길이 10~30초 vs 10~32초, 학습률 1e-5 vs 3e-5). 출처를 구분해서 쓰면 오히려 장점이 됩니다
- **논문 수치와 우리 측정 수치를 섞는 것**: 표에 "출처" 열을 두거나 `(논문)`, `(측정)`을 붙이세요
- **과장**: "완벽히 재현", "최초로" 같은 표현은 피하고, "논문 보고값과 일치함을 확인" 정도로 사실만
- **용어 혼용**: 한 번 정한 용어는 끝까지 같은 것으로 (아래 4-4)
- **방법 설명의 오류**: X-Pool의 query는 **텍스트**, key/value는 **프레임**입니다. 반대로 쓰면 이해 부족으로 보임
- **복사 흔적**: 논문 문장을 번역해서 옮기는 것은 피하고, 그림도 직접 다시 그리세요

### 4-3. 문장을 쓸 때
- 각 절 첫 문장에 **그 절의 결론**을 두고, 근거를 뒤에 붙이면 읽기 쉬움
- 후속 연구는 "X-Pool은 ~했지만, A는 ~를 문제로 보고 ~했다"처럼 **X-Pool을 주어로 한 대비 구조**를 쓰면 리뷰가 하나로 엮임
- 2.3.2 → 2.3.3처럼 "앞 방법의 한계를 다음 방법이 지적"하는 연결 문장을 각 절 끝에 한 줄씩
- 개조식을 그대로 붙여넣지 말고, 이유·결과를 이어주는 접속어(그래서, 반면, 이를 위해)로 문단화

### 4-4. 용어 통일표 (첫 등장 시 영문 병기, 이후 한글만 또는 약어만)
